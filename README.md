# Аманат — MVP платформы доверия

Рабочая версия бесплатного каталога мусульманских специалистов. Профиль не публикуется автоматически: заявка проходит ручную модерацию, а затем создаётся и публикуется из защищённой панели.

## Возможности

- каталог с поиском и фильтрами по категории, стране, городу и формату работы;
- публичные профили только со статусом `published`;
- реальная отправка заявки в Supabase с проверкой данных, honeypot-полем и ограничением повторной отправки;
- вход для модератора, смена статусов, внутренние заметки, созвон и журнал действий;
- создание профиля из одобренной заявки, публикация и временное скрытие;
- отзывы и жалобы с обязательной модерацией;
- RLS-политики, роли `moderator` и `admin`, отдельное хранилище аватаров с ограничением типа и размера.

## Запуск на Windows

1. Установите Node.js LTS.
2. Скопируйте `.env.example` в `.env.local` и заполните переменные Supabase.
3. Установите пакеты: `pnpm install` (либо `npm install`).
4. Запустите проект: `pnpm dev`.
5. Откройте адрес, который покажет сервер разработки.

## Настройка Supabase

1. Создайте проект в Supabase.
2. В SQL Editor выполните содержимое `supabase/schema.sql` на новом проекте.
3. Скопируйте URL проекта и anon key в `.env.local`.
4. В разделе Authentication создайте пользователя-модератора.
5. В SQL Editor назначьте ему роль: `insert into public.moderators (user_id, role) values ('UUID_ПОЛЬЗОВАТЕЛЯ', 'admin');`.
6. Удалите или замените демонстрационную запись после проверки запуска.

`SUPABASE_SERVICE_ROLE_KEY` предусмотрен только для будущих защищённых служебных операций; клиентский код его не читает.

## Проверка качества

- `pnpm typecheck` — проверка TypeScript;
- `pnpm test` — модульные проверки валидации заявки;
- `pnpm lint` — статическая проверка;
- `pnpm build` — production-сборка.

## Развёртывание

Разместите приложение на Vercel или другом хостинге Next.js и задайте три переменные из `.env.example` в настройках окружения. В Supabase добавьте URL развернутого сайта в разрешённые Redirect URLs для авторизации.

## Структура данных и роли

Основные таблицы — `applications`, `specialists`, `reviews`, `complaints`, `audit_log`, `categories`, `moderators`. Публичный доступ ограничен опубликованными профилями и одобренными отзывами. Модератор ведёт заявки, профили, отзывы и жалобы; только администратор управляет категориями и ролями.
